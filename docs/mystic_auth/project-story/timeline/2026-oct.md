### Commit 81: 11 October, 2026

"Tracked refresh-token reuse and shipped dependency notices in images"

- Corrected rate-limit dashboard matching and improved signup and email lifecycle handling, session events, frontend routing, and shared UI behavior across the authenticated application.
- Added a PostgreSQL table to track consumed refresh tokens, with one row per token containing its ID, consumption time, expiry, client IP, and `account_ver` and `chain_ver` values. The unique token ID lets separate processes detect a second use; expired rows are removed by the scheduled session cleanup task. The JWT itself and its other claims are not stored.
- Added operational scripts for authorization-cache invalidation and conditioned-grant conflict reporting, with generated third-party license notices for backend and frontend dependencies.
- Checked production Compose service networks, shipped backend and frontend dependency notices in the images, and fixed the nginx notice smoke to resolve its configured backend upstream without joining the app network.

- Added sixteen backend unit cases for authorization-maintenance commands and `/auth/me` failure handling, plus four frontend regressions for shell extensions, accessible chart tooltips, 90-day label thinning, and refetch feedback.
- Corrected the backup-network regression and deployment documentation to reflect the private `postgres_net` plus dedicated non-internal egress topology.
- Reconciled session, token-revocation, audit-retention, worker-schedule, and account-lifecycle documentation with the Postgres-backed implementation; corrected template ownership and app-content namespace guidance, updated legal translations and environment examples, and added the missing integration-secret contract page.
