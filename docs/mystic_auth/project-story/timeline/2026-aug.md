### Commit 69: 29 August, 2026

`dea159d`: "Implemented granular permissions, bulk actions, and scheduled backups"

The largest single commit in the project's history by line count.

- Fixed a duplicate security-header bug in `nginx.frontend.conf`.
- Fixed a `DATABASE_URL` override that silently shadowed `env_file` and had broken the stack mid-audit.
- Fixed a hardcoded Docker subnet collision between the two production-style Compose files.
- Fixed a pydantic circular-reference flake in policy list serialization, by building schemas row by row.
- Rebuilt the PBAC frontend surface: bulk actions on the Users page, the permission catalog, and an effective-permissions viewer, verified across themes, font sizes, and languages.
- Attacked the backend directly the way a real attacker would (forged JWTs, IDOR, mass assignment, privilege self-granting, IP spoofing, and more), all correctly blocked.
- Added client-side length validation matching the backend's limits.
- Added a `Retry-After` header with a translated wait-time message on login lockout.
- Closed the "backups are scripted but nothing schedules them" gap with an on-by-default `db_backup` service on both production Compose files.
- Swept the docs for staleness, including the PBAC component table and color-coded flow diagrams; trimmed comments across all files and tests to be concise. See the [security decisions](../../security/decisions.md) and [concerns](../../concerns/README.md) pages for the lasting details.
